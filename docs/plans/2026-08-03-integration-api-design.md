# 进销存对接 API v1 设计

## 决策

在现有 Next.js 应用内增加版本化只读接口 `/api/v1`，不拆分新的服务，也不允许第三方系统修改内部编码或商品数据。

## 原因

- 当前为单人内部系统，模块化单体比微服务更容易部署和备份。
- 商品编码系统继续作为商品、SKU 和编码映射的唯一数据源。
- 第一阶段只读可显著降低错误同步导致的数据损坏风险。
- 固定响应结构和 OpenAPI 规范方便未来替换或增加进销存系统。

## 接口

- `GET /api/v1/health`：公开健康检查。
- `GET /api/v1/skus`：认证后分页读取 SKU。
- `GET /api/v1/skus/{internalCode}`：认证后按永久内部编码读取。
- `GET /api/v1/lookup?code=`：认证后用任意关联编码反查。

## 非功能要求

- 数据接口使用 API Key，支持 `Authorization: Bearer` 和 `X-API-Key`。
- API Key 不进入 Git 仓库，使用服务器环境变量配置。
- 每页最多 100 条；错误使用固定错误码；停用记录返回明确警告。
- 部署前后执行 SQLite 一致性备份和完整性检查。

## 后续扩展

确定进销存产品及其接口文档后，再增加库存回传、Webhook、幂等键和同步日志；不在 v1 中预设未经确认的写入协议。
