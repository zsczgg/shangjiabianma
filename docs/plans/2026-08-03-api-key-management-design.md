# API Key 后台管理设计

## 目标

让系统管理员在现有商品编码后台中为不同进销存、库存系统或开发者创建独立 API Key，并能查看使用状态和安全停用。

## 设计决策

- 每套对接系统使用独立密钥，不共享一个全局密钥。
- 数据库保存 SHA-256 鉴权哈希，并使用服务器独立密钥以 AES-256-GCM 加密保存完整密钥，方便管理员后续查看。
- 列表长期显示名称、掩码、状态、创建时间、最近使用时间和停用时间。
- 使用中的密钥不能删除；停用后可由管理员确认并永久删除。
- 服务器旧密钥继续兼容；至少创建一个新密钥后才允许停用旧密钥。
- 当旧密钥已停用时，不允许停用最后一个有效新密钥，避免把 API 完全锁死。

## 安全边界

`/api/v1` 只依赖 API Key，便于第三方系统调用；`/api-management` 和 `/api/api-keys` 仍受现有后台网页密码保护。完整密钥只以密文进入 SQLite 备份，不进入 GitHub 或日志。服务器上的 `API_KEY_ENCRYPTION_SECRET` 必须与数据库一起备份，否则密文无法恢复。

## 失败处理

- 创建失败不产生半条记录。
- 停用已经停用的密钥视为成功，保证重复操作安全。
- 老版本只保存哈希的密钥无法恢复完整内容，管理员需新建替代密钥。
- 密钥无效或停用后，业务 API 固定返回 HTTP 401。
- 最近使用时间最多每分钟更新一次，减少 SQLite 写入竞争。
