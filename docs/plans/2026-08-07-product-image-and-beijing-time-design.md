# 商品图片上传与北京时间设计

## 目标

商品图片以网页直接上传为主，同时保留外部图片 URL 作为备用。上传文件保存在 `/data/uploads/products`，与 SQLite 数据库共用服务器持久化目录，因此 Docker 更新不会删除图片。数据库继续只保存图片地址，不引入破坏性迁移。

## 图片流程

- 新建和编辑商品时可选择 JPG、PNG 或 WebP 图片，单张最大 5 MB。
- 上传接口校验文件大小、类型与文件头，使用随机文件名写入持久化目录。
- `/uploads/products/[filename]` 负责读取图片并设置长期浏览器缓存。
- 表单上传成功后立即预览，保存商品时仍通过现有 `imageUrl` 字段写入数据库。
- 原 URL 输入保留为备用；上传图片和 URL 共用同一个最终图片地址。
- 商品列表、商品详情和已有标签功能都读取同一个图片字段。

## API 兼容性

现有 API 字段不删除。商品对象继续返回 `imageUrl`，并新增 `imageSource`。上传图片地址在 API 响应中转换为完整 URL，外部系统可以直接展示；无图片时返回 `null`。

## 时间

数据库继续使用标准时间存储，显示层统一指定 `Asia/Shanghai`，避免服务器时区影响。顶部加入客户端实时北京时间，每秒刷新。Docker 容器同时设置 `TZ=Asia/Shanghai`，便于日志和运维时间保持一致。

## 验证

测试文件类型识别、图片地址转换和 API 序列化；运行完整测试、类型检查和生产构建；浏览器验证上传预览、列表缩略图、详情图片与实时时钟。
